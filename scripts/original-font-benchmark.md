# 원본 글꼴 편집 성공률 측정

실제 PDF와 수정 작업을 고정한 로컬 테스트로 측정한다. 합성 회귀 테스트의 통과율을 실제 문서 성공률로 표시하지 않는다.

1. 한글·Word·PowerPoint에서 만든 실제 문서를 고르게 선정한다. 권한 제한 문서는 편집 성공률 대상과 분리해 별도로 검증한다.
2. 문서별 문장 변경·글자 추가·삭제 작업을 정하고, 개선 전후에 동일한 목록을 사용한다. 실패한 작업을 분모에서 제거하지 않는다.
3. PDF와 수정 문구는 로컬에만 둔다. 아래 목록을 `benchmark.local`에 저장하면 Git에서 제외된다. ID에는 개인정보 대신 임의 번호를 사용한다.

```json
[
  {
    "id": "word-001-add",
    "path": "samples/word-001.pdf",
    "page": 0,
    "before": "선택할 문단의 전체 내용",
    "after": "수정한 문단의 전체 내용입니다."
  }
]
```

```powershell
cargo run -p pdf-core --example original_font_benchmark -- apps/desktop/src-tauri/resources/pdfium/pdfium.dll benchmark.local
```

페이지는 0부터 시작하고 상대 파일 경로는 목록 파일 기준이다. 내용이 같은 문단이 여러 개면 선택 모호성으로 실패 처리한다. 현재 도구는 문단 편집 경로를 측정하며 객체 단위·스캔 OCR 편집을 대표하지 않는다.

성공은 원본 글꼴 경로로 반영, 글꼴 이름 유지(부분 글꼴 접두사 제외), 엔진의 비편집 영역 보존 검증, 새 PDF 저장, 재열기 화면 일치, 원본 파일 유지까지 통과한 경우다. 이름이 바뀌는 내장 글꼴은 보수적으로 실패 처리하므로 결과의 실패 단계를 함께 검토한다. 자동 대체 글꼴은 요청하지 않는다.

JSON 보고서는 임의 작업 ID, 성공 여부, 실패 단계, 처리 시간과 전체 성공률만 출력한다. 문서 경로·본문은 출력하지 않는다. 60% 미만이면 종료 코드 1을 반환한다. 임시 저장 결과는 실행 후 삭제하고 사용자 원본은 덮어쓰지 않는다.

실제 문서 목록이 아직 제공되지 않았으므로 현재 대표 문서 성공률은 **미측정**이다. 60% 달성 여부는 대표 목록을 확정하고 실행한 뒤 판단한다.

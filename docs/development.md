# Paperkit

기존 PDF의 개별 텍스트 객체를 직접 수정하는 Tauri 2 데스크톱 편집기.
파일 선택/드롭, 미리보기, 페이지 탐색, 읽기 전용 모드와 개별 텍스트 객체 편집을 지원합니다.
편집 모드에서 글꼴 변경, Undo/Redo, 새 PDF 저장과 재열기 검증을 제공합니다.
문단 블록을 클릭하면 선택하고, 더블 클릭하면 본문 위치에서 직접 입력합니다. 선택 상자를 드래그하면 실제 PDF 텍스트 객체가 이동합니다.
PDF에 포함된 재사용 가능한 원본 글꼴은 실제 글꼴 데이터를 화면에 로드하고 PDF 편집에도 사용합니다. 원본의 문자 매핑이나 글리프가 부족하면 제공 글꼴로 대체합니다.
완전한 문단 블록은 모서리로 크기를 조절하고, 기존 줄 수보다 긴 내용을 입력할 수 있습니다. 추가 줄은 페이지 안에서 자동으로 늘어납니다.
입력 중에는 선택한 원문 텍스트를 제외한 임시 페이지 배경을 사용해 표·이미지·배경색을 가리지 않습니다.
혼합 서식·문장 범위 수정은 글자 수·공백 위치 유지 조건이며 지원 폰트와 레이아웃에는 제한이 있습니다.
적용/Ctrl+Enter 또는 저장·페이지 이동 시 실제 PDF에 반영하며 실패한 입력은 보존합니다.
최신 구현 범위는 [개발 체크리스트](development-checklist.md)를 참고하세요. 아래 날짜별 검증 기록은 당시 결과입니다.

## 구조

```text
apps/desktop/
  src/                 React UI, Zustand 상태, IPC 호출
  src-tauri/           Tauri 실행 진입점, Commands, IPC DTO
crates/pdf-core/       Tauri 비의존 Rust 라이브러리
docs/pdfium-integration.md
Cargo.toml            Cargo workspace
pnpm-workspace.yaml   pnpm workspace
pnpm-lock.yaml        프론트엔드 의존성 잠금
```

React 19, TypeScript 5.9, Vite 6, Tailwind CSS 4, Zustand 5를 사용합니다.
현재 설치된 Node 22.14와 호환되는 Vite 6을 선택했습니다.
서버, Turborepo, 공유 UI 패키지, 사용하지 않는 PDF 의존성은 추가하지 않았습니다.

`pdf-core`는 Tauri에 의존하지 않습니다. `document.rs`의 `inspect_pdf_file()`에서 파일을
읽기 전용으로 확인하며, Tauri Command는 `spawn_blocking`에서 이를 호출하고 DTO로 변환합니다.
UI는 IPC 응답을 런타임에도 검증합니다. Rust의 `selection.rs`가 선택 정보·파일 ID·요청 번호를 소유하며,
Zustand는 직렬화한 상태를 화면에 반영합니다. 네이티브 핸들은 전달하지 않습니다.
파일 ID는 현재 앱 실행 중 선택을 식별하는 값이며, 아직 열린 PDFium 문서 ID는 아닙니다.
`render.rs`의 전용 worker는 선택 ID에 대응하는 PDFium 문서와 원본 바이트 스냅샷을 보관합니다.
PDFium 네이티브 핸들은 이 스레드를 벗어나지 않습니다.

- Rust stable MSVC 툴체인 (`rustup`, `cargo`, `rustc`, `rustfmt`, `clippy`)
- Visual Studio Build Tools: **Desktop development with C++**, MSVC 및 Windows SDK
- Microsoft Edge WebView2 Runtime

설치는 [Tauri 공식 사전 요구사항](https://v2.tauri.app/start/prerequisites/)을 따릅니다.
설치 후 새 터미널에서 `cargo --version`, `rustc --version`을 확인합니다.

## 실행

루트 폴더에서 실행합니다. 프론트엔드 패키지 설치에는 pnpm만 사용합니다.

```powershell
pnpm install --frozen-lockfile
pnpm setup:pdfium # 최초 1회: Windows x64 PDFium 다운로드·SHA-256 검증·라이선스 준비
pnpm setup:fonts  # 최초 1회: 고정 버전 폰트 5종과 라이선스 준비
pnpm dev:web      # 브라우저 UI: http://127.0.0.1:1420
pnpm dev          # 네이티브 Tauri 개발 앱 (Rust/C++ 도구 필요)
```

PowerShell 실행 정책이 `pnpm.ps1`을 차단하면 `pnpm.cmd`를 사용합니다.
브라우저 미리보기에서는 Rust 명령을 호출하지 않고 해당 모드를 표시합니다.
네이티브 앱에서는 파일 선택 버튼과 점선 드롭 영역을 사용할 수 있습니다.
브라우저 미리보기에서는 파일 선택 버튼이 비활성화됩니다.

```powershell
pnpm typecheck
pnpm test:web                  # UI + Zustand + IPC adapter (IPC 모의 처리)
pnpm test:pdfium               # 실제 PDFium DLL 로딩/렌더링 테스트 (setup:pdfium 필요)
pnpm test:fonts                # 폰트 교체·한글 수정·Undo/Redo·저장/재열기 (setup:fonts 필요)
pnpm test:layout               # 글자별 PDF 문장 복원·일괄 수정·롤백·저장 (setup:pdfium 필요)
pnpm build:web                 # TypeScript 검사 + Vite 프로덕션 빌드
pnpm fmt:rust
pnpm check:rust
pnpm test:rust
cargo test -p pdf-core         # Tauri와 분리된 core 검증
pnpm build                    # 네이티브 빌드 및 플랫폼 설치 패키지
```

Cargo 출력은 루트 `target/`, 프론트엔드 출력은 `apps/desktop/dist/`입니다.
`Cargo.lock`과 `pnpm-lock.yaml`을 함께 유지합니다.

## 파일 입력 1단계 (이전 구현 기록)

구현: PDF 필터가 있는 단일 파일 선택 창, 드롭 영역 강조/해제, 두 입력 경로의 공통
`receive_file_input` Command, 여러 파일/빈 경로 거절, 받은 경로 표시.
선택 취소나 잘못된 입력은 이전 경로를 유지합니다. 파일을 읽거나 수정하지 않습니다.
드롭 영역 밖에 놓은 파일은 처리하지 않습니다.

Rust 테스트는 복수/빈 경로 거절과 한글·공백 경로 전달을 검증합니다.
이번 변경은 `pnpm build:web`, `cargo test --workspace`(2개 통과),
`cargo check --workspace`를 통과했습니다.
실제 Windows 대화상자와 탐색기 드롭은 아래 수동 점검이 필요합니다.

- [ ] 파일 선택 → PDF 한 개 선택 → 경로 표시
- [ ] 선택 창 취소 → 이전 경로 유지
- [ ] 점선 영역 진입/이탈 → 강조/해제
- [ ] 파일 한 개 드롭 → 경로 표시
- [ ] 여러 파일 드롭 → “PDF 한 개만 선택해 주세요” 안내, 이전 경로 유지
- [ ] Windows 배율 100%/150%에서 영역 안/밖 드롭 확인

위 기록은 경로만 받던 1단계 기준이며, 현재는 아래 2단계 검증을 수행합니다.

## 파일 검증 및 홈 화면 2단계

- 헤더·소개·연결 상태·푸터를 제거하고 중앙의 점선 업로드 영역 하나로 구성.
- 업로드 아이콘 → 안내 문구 → 파일 선택 버튼 순으로 배치. 드롭 강조 유지.
- 존재하지 않는 파일, 폴더, 빈 파일, 비PDF 확장자, 잘못되거나 짧은 헤더, 읽기 실패 거절.
- `.PDF` 등 대소문자 확장자와 한글·공백 경로 지원.
- 파일 시작의 `%PDF-1.0`~`%PDF-1.7` 또는 `%PDF-2.0`과 줄바꿈을 확인. 앞에 다른 바이트가 있는 비표준 파일은 현재 거절.
- 최대 9바이트만 읽어 헤더 확인. 원본 쓰기·수정·외부 전송 없음.
- 성공 시 파일명·크기·경로 표시. 취소/검증 실패 시 기존 정보 유지.
- 헤더 확인만으로 손상·암호화 여부나 PDF 구조 유효성을 판정하지 않음. PDFium 로딩에서 추가 검증 예정.

헤더 기준 참고: [Adobe PDF 1.7 문서](https://opensource.adobe.com/dc-acrobat-sdk-docs/standards/pdfstandards/pdf/PDF32000_2008.pdf).

검증: 프론트엔드 프로덕션 빌드, Rust 테스트 8개, `cargo check --workspace` 통과.
브라우저 미리보기 1200×800 캡처에서 중앙 업로드 영역 배치 확인.
테스트는 잘못된 입력, PDF 1.7/2.0 헤더, 한글·공백·대문자 확장자,
Windows 읽기 잠금, 오류 분류, 원본 바이트 보존을 포함합니다.
ACL 권한 거절은 오류 매핑 테스트이며 실제 Windows ACL 변경 테스트는 수행하지 않았습니다.
네이티브 파일 선택/드롭 및 화면 배율별 조작은 수동 확인이 필요합니다.

## 선택 상태 3단계

- Rust managed state에서 선택된 파일 정보와 ID를 보관. 성공한 선택마다 새 ID 발급.
- `idle / restoring / checking / clearing / selected / error` 상태를 UI에서 구분.
- 선택 해제 버튼은 파일 확인 중에도 사용 가능. 해제 이후 도착한 이전 검증 결과는 무시.
- 새 파일 검증 실패와 파일 선택 창 취소 시 기존 선택 유지.
- 요청 번호로 순서를 비교해 늦게 도착한 요청/결과가 최신 선택을 덮어쓰지 않도록 처리.
- 같은 앱 실행 중 화면 새로고침 시 Rust에서 선택 상태 복원. 이전 화면의 진행 중 검증은 무효화.
- 앱을 완전히 종료하면 선택 정보는 사라짐. 디스크 영구 저장은 하지 않음.
- 복원은 메타데이터 복원이며, 파일이 외부에서 삭제/변경되었는지는 다음 실제 문서 열기에서 재검증해야 함.

프론트엔드 빌드와 Rust 테스트 12개 통과. 새 테스트 4개는 응답 역전, 최신 요청 실패,
확인 중 선택 해제, 화면 재연결을 검증합니다. 실제 네이티브 UI 통합 조작은 별도 수동 확인이 필요합니다.

- [ ] PDF 선택 → 선택 해제 → 초기 화면 복귀
- [ ] PDF 선택 → 다른 파일 선택 창 취소 → 기존 선택 유지
- [ ] PDF 선택 → 잘못된 파일 드롭 → 오류와 기존 선택 표시
- [ ] 연속 드롭 → 마지막 요청 결과 반영
- [ ] 확인 중 선택 해제 → 뒤늦게 파일 정보가 나타나지 않음
- [ ] 화면 새로고침 → 선택 정보 복원 (앱 전체 재시작은 초기화)

## 파일 입력 통합 검증 4단계

실행: `pnpm test:web`, `cargo test --workspace`, `pnpm build:web`, `cargo check --workspace`.

- UI 통합 테스트 8개: React 컴포넌트, Zustand, IPC 응답 파서를 함께 실행.
  네이티브 `invoke`, 파일 선택 창, 드래그 이벤트만 모의 처리한다.
  선택→해제, 취소, 확인 중 해제, DPR 1.5 좌표, 영역 밖 드롭 무시,
  오류 시 선택 보존, 응답 역전, 잘못된 IPC 응답/재연결, 브라우저 모드 등을 확인한다.
- Rust 테스트 13개: 기존 core 검증과 함께 실제 임시 파일을 사용하는 Command 처리 흐름 테스트를 추가.
  검증→선택→잘못된 헤더/복수 입력 거절→기존 선택 보존→해제→오래된 요청 거절→재선택 및 원본 보존을 확인한다.
- 발견/수정: 파일 선택 대화상자가 닫힌 뒤에도 검증 완료까지 `choosing` 상태가 유지되어
  선택 해제가 비활성화되던 문제. 대화상자 종료와 파일 검증의 수명을 분리했고 회귀 테스트를 추가했다.

자동화는 실제 Windows 파일 선택 창, 탐색기 드롭, WebView2 IPC 전송 자체를 실행하는 네이티브 E2E가 아니다.
위 수동 점검 항목은 자동화 테스트 통과만으로 완료 표시하지 않는다.
이제 다음 개발 단계는 PDFium 바이너리 연동과 실제 문서 로딩/미리보기다.

## PDFium 로딩 및 미리보기 5단계

구현 완료: Windows x64 PDFium 151.0.7881.0 + `pdfium-render =0.9.4`.
`scripts/pdfium-manifest.json`에 바이너리 URL/해시를 고정하고 `pnpm setup:pdfium`에서 검증합니다.
DLL과 라이선스는 `src-tauri/resources/pdfium/`에 준비되며 Tauri resources로 함께 패키징됩니다.
이 폴더는 생성물로 Git에서 제외합니다. 새 체크아웃에서는 개발/패키징 전에 setup 명령을 실행해야 합니다.
개발 앱은 명시적 프로젝트 경로, 배포 앱은 Tauri resource 경로로 로딩합니다. 시스템 DLL 검색으로 폴백하지 않습니다.

- PDF 선택 후 같은 점선 블록에서 파일명·크기·경로와 오른쪽 첫 페이지 썸네일 확인. “다른 파일 선택” 또는 “PDF 열기” 제공. 선택 해제 버튼은 제거.
- “PDF 열기”를 눌렀을 때 미리보기로 이동. 전체 페이지 수, 이전/다음 페이지, 50~200% 확대.
- 열린 문서 왼쪽에 전체 페이지를 스크롤하는 썸네일 목록 표시. 클릭 시 해당 페이지로 이동하고 현재 페이지 강조.
- 상단의 “페이지” 버튼으로 사이드바 접기/펼치기. 접었을 때 썸네일 요청을 멈추고 다시 펼치면 선택 페이지와 캐시 유지.
- 닫기 버튼으로 문서를 해제하고 업로드 화면으로 복귀.
- PDFium worker 하나에서 로딩/렌더링을 직렬 처리. 문서 바이트를 소유해 원본 잠금 없이 같은 스냅샷을 표시.
- 최대 파일 크기 128 MiB. 이미지 최대 폭 1600px, 높이 2200px. 매우 긴 페이지는 높이 제한에 따라 더 작게 렌더링될 수 있음.
- 한 번에 한 문서만 보관. 편집/저장 전까지 원본은 수정하지 않음.
- 암호 요구·잘못된 문서·읽기 실패·엔진 누락·잘못된 페이지를 구분하여 안내.
- 암호 입력, 텍스트 선택/수정, 썸네일, 파일 변경 감시, 다른 OS/아키텍처는 미지원.

검증: UI 테스트 12개, 일반 Rust 테스트 13개, 프론트엔드 빌드, Rust 컴파일 검사 통과.
별도로 `pnpm test:pdfium`의 **실제 DLL 테스트 1개**도 통과했습니다.
이 테스트는 직접 만든 2페이지 PDF의 페이지 수·빨강/파랑 픽셀·PNG 크기·페이지 범위·문서 스냅샷·해제·손상 파일·DLL 누락·원본 보존을 확인합니다.
일반 `cargo test`에서는 이 DLL 테스트를 명시적으로 ignored 처리하므로 전용 명령을 별도로 실행해야 합니다.
실제 암호 PDF 표본, 설치 프로그램 배포, Windows UI 전체 E2E는 아직 미검증입니다.

다음 구현 대상은 PDF 텍스트 객체와 좌표 추출 및 클릭 선택입니다.

파일 확인 화면 변경 검증: UI 테스트 14개와 프론트엔드 빌드 통과.
파일 선택만으로 미리보기를 열지 않는지, 확인 버튼으로 전환하는지,
다른 파일을 선택하면 새 파일 정보로 확인 단계가 유지되는지를 테스트합니다.

썸네일 화면 변경: 확인 단계에서 첫 페이지를 실제로 렌더링하며, 전체 문서 화면 진입만 “PDF 열기” 버튼으로 제어합니다.
페이지 목록은 전체 스크롤 길이를 유지하고 화면 주변 행만 렌더링합니다. 썸네일을 순차 요청하고 최대 64장만 메모리에 보관합니다.
이번 검증은 UI 테스트 17개 및 타입 검사/프로덕션 빌드 통과. IPC 모의 테스트에서 썸네일 클릭 이동,
100페이지 목록 스크롤, 재선택 뒤 이전 파일 이미지 무시를 확인했습니다. 네이티브 UI 조작은 별도 확인이 필요합니다.

사이드바 접기/펼치기 추가 후 UI 테스트 18개와 타입 검사/빌드 통과.
확인용 이미지 아래 “첫 페이지” 문구는 제거했으며 접근성 대체 텍스트는 유지합니다.
이후 전체 개발 순서와 단계별 완료 기준은 [MVP 개발 체크리스트](development-checklist.md)를 참고하세요.

## 텍스트 선택·제한적 편집·저장

이 절과 개발 체크리스트가 현재 상태입니다. 위 단계별 기록의 미지원/다음 단계 설명은 당시 기준입니다.

PDF를 열고 글자를 클릭하면 오른쪽에 객체의 내용과 속성이 표시됩니다. 지원되는 객체는 내용을 바꾸고
“적용”을 누르면 기존 PDF 텍스트 객체가 수정됩니다. 페이지 위에 새 텍스트를 덮어쓰지 않습니다.
기본 비임베디드 Helvetica/Courier/Times 폰트의 ASCII 문자만 편집하며, 한글/서브셋/임베디드 폰트는
텍스트 추출과 선택만 지원합니다. 객체별 제한 사유를 표시합니다. 새 글자가 기존 영역을 벗어나면 거절합니다.

수정은 복제 문서에서 수행하고 재열어 내용·속성·주변 픽셀 보존을 검증한 후 반영합니다.
실패하면 활성 문서와 입력은 유지됩니다. Undo/Redo는 Rust 스냅샷 이력으로 처리합니다.
Ctrl+Z, Ctrl+Y 또는 Ctrl+Shift+Z, Ctrl+S를 지원합니다. 입력창 내부의 Undo는 기본 입력 기능을 따릅니다.

“새 PDF로 저장”은 원본을 포함한 모든 기존 파일의 덮어쓰기를 거절합니다.
같은 폴더의 임시 파일에 쓰고, 재열어 전체 페이지의 텍스트와 렌더 픽셀을 확인한 후 새 경로로 확정합니다.
최종 확정에 하드링크를 사용하므로 지원되지 않는 파일시스템에서는 오류가 납니다. 우선 로컬 NTFS 폴더를 사용하세요.
미저장 문서를 닫거나 앱을 종료하면 확인합니다. 편집/저장 처리 중에는 중복 작업과 종료를 막습니다.

편집 스냅샷은 32 MiB 이하, undo 이력은 최대 20개/128 MiB입니다. 미리보기 로딩 한도는 기존의 128 MiB입니다.
전체 페이지를 검증하기 때문에 긴 문서는 수정·저장에 시간이 걸릴 수 있으며 진행률/취소는 아직 없습니다.

검증: UI 테스트 23개, 일반 Rust 테스트 13개, 실제 DLL 통합 테스트 1개, 타입 검사/프론트엔드 빌드 통과.
DLL 테스트는 영문 객체 수정, 원본/주변 보존, 길이 초과/잘못된 revision 거절, Undo/Redo,
저장/재열기, 회전/CropBox 좌표, 한글 임베디드 폰트 추출, 권한 제한/암호 문서를 확인합니다.
실제 Windows UI 조작과 별도 PC 설치 검증을 대체하지는 않습니다.

Windows NSIS 배포 빌드도 통과했습니다: `pnpm --filter @paperkit/desktop tauri build --bundles nsis`.
생성 파일은 `target/release/bundle/nsis/Paperkit_0.1.0_x64-setup.exe`입니다.
설치 스크립트의 PDFium DLL/라이선스 포함 경로와 번들 DLL 해시를 확인했으며,
이 설치 파일을 별도 PC에 설치하는 검증은 아직 수행하지 않았습니다.

## 읽기 전용 기본값과 본문 입력 UI

새로 연 PDF는 기본 읽기 전용입니다. 헤더 아래의 ‘편집 사용’을 누르면 본문 텍스트를 클릭할 수 있습니다.
오른쪽 속성 패널 대신 클릭한 글자 위치에 임시 입력창을 표시합니다. 적용 버튼 또는 Ctrl+Enter로 반영하며,
IME 조합 중에는 적용/선택 취소 단축키를 처리하지 않습니다. 원본 파일 보호와 기존 폰트 제한은 그대로입니다.

페이지 사이드바는 빠르게 스크롤해도 요청 하나만 진행하고 완료 후 최신 화면 범위부터 불러옵니다.
오류/높이 변화가 선택 페이지로 스크롤을 되돌리지 않도록 수정했습니다. UI 테스트 27개 및 타입 검사/빌드 통과.
이 UI 변경 후 Windows 설치 파일은 다시 생성하지 않았습니다. 개발 확인은 `pnpm dev`를 사용합니다.

문장 단위 편집은 먼저 [공식 문서 기반 벤치마킹과 복원 기준](text-editing-benchmark.md)을 정리했습니다.
문장 자동 병합/여러 객체 일괄 수정은 아직 구현하지 않았습니다. 열기 제한 128 MiB,
편집·저장 스냅샷 제한 32 MiB는 이번 작업에서 변경하지 않았습니다.

페이지 탐색은 이제 문서 뷰어 하단 중앙에 표시됩니다. 현재 페이지 번호에 이동할 번호를 입력하고
Enter를 누르면 이동하며 Escape로 현재 번호를 복원합니다. 잘못된 번호는 안내하고 이동하지 않습니다.
본문/썸네일과 번호를 동기화하며, 미적용 편집이 있으면 이동 전 확인합니다.
이번 UI 변경 검증은 테스트 30개와 TypeScript/프로덕션 빌드 통과입니다.

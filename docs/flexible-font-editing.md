공식 문서 벤치마킹을 반영한 2026-10-10 변경입니다. 외부 편집기에 사용자 PDF를 업로드하지 않았습니다.

- iLovePDF: 기존 텍스트 직접 편집과 서식 유지 UX. 내부 글꼴 매칭 알고리즘은 공개 자료로 확인하지 못했습니다.

- Acrobat: 편집용 fallback과 자간·행간·가로 배율 등 서식 감지.

  https://support.apryse.com/support/solutions/articles/35000251323-editing-text-content

## 구현

더블 클릭할 때 각 원본 객체의 글꼴을 먼저 준비합니다. 원본 사용이 불가능한 구간만 기본 제공 정적 글꼴로 대체합니다. 글꼴명에서 고딕·명조·고정폭 계열과 굵기를 분류하며, Noto 가변 글꼴의 기본 Thin을 Regular로 취급하지 않습니다. 대체 사실과 실제 글꼴을 화면에 표시합니다.

편집 진입만으로 PDF를 변경하지 않습니다. Enter 또는 적용 시 선택된 원본 객체 ID별 대체 글꼴 목록과 내용을 원자적으로 전달합니다. 문단 내 다른 구간의 원본 글꼴·크기·색상은 기존 flow 경로로 보존합니다. 서버는 지정된 객체들이 선택 영역에 속하는지 재검증하며 기존 권한·기하·저장 검증을 유지합니다. 취소 시 원본은 그대로입니다.

적용 직전에는 새 입력의 글리프 지원 여부도 검사합니다. 기존 서브셋에 새 문자가 없으면 해당 구간에 사용할 대체 글꼴을 검사합니다. 어떤 후보도 문자를 지원하지 않으면 입력을 유지하고 오류를 표시합니다. 원본 글꼴 데이터 확인 API는 입력 문자열을 받아 검사할 수 있으며 문서를 변경하지 않습니다.

## 범위와 제한

- 대체 범위는 글리프 하나가 아니라 원본 객체에 대응하는 서식 구간입니다.
- 여러 곳을 한 번에 바꾼 내용의 스타일 배정은 기존 공통 접두·접미 구간 방식입니다. 완전한 rich-text 편집 이력 추적은 아직 아닙니다.
- 폰트 계열·굵기 매칭은 이름 기반입니다. 글리프 외형과 글자 폭을 비교하는 시각적 최적 매칭은 아직 아닙니다.
- 원본 데이터의 OTF/CFF 지원 확대, 공식 글꼴 자동 다운로드는 이번 변경에 포함하지 않았습니다.
- 동일 글꼴을 못 찾으면 모양과 줄바꿈이 달라질 수 있습니다. 회전·클리핑·복잡한 경계 등 구조적 편집 제한은 유지됩니다.
- 사용자 스크린샷의 실제 PDF는 작업 폴더에 없어 직접 재현하지 못했습니다. 합성 PDF로 구간별 글꼴 유지, 저장·재열기, Undo를 검증합니다.

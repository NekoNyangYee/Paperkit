# 입력 적용과 이동 지연 개선

- Enter로 적용, Shift+Enter로 줄바꿈. IME 조합 중 Enter 및 키 반복으로는 적용하지 않는다. 단축키는 React 초안 상태보다 입력 DOM의 최신 텍스트를 우선한다.
- 적용 후 새 페이지가 준비되면 이전 초안과 편집 상태를 정리한다. 다른 블록으로 편집을 이어가는 경우 및 글꼴 변경 후 선택 복원은 유지한다. 실패한 초안은 남긴다.
- `Tc`/`Tw`/`TJ`가 있는 수정 대상 외의 문장이 PDFium 콘텐츠 재생성 때 바뀌어 VerificationFailed가 발생하는 사례를 재현했다. 원래 객체의 글꼴·텍스트·행렬로 비대상 객체를 대응시켜 자간/단어 간격을 복원하고 기존 전체 검증을 수행한다. 대응이 불확실하면 추측해서 적용하지 않는다. 블록 편집, 기존 문단 편집, 객체 편집 경로에 적용했다.
- 이동은 모든 PDF 객체의 직렬화 보존을 구조적으로 검사하고, 바뀐 페이지만 텍스트/이미지로 검증한다. 예를 들어 9페이지 문서는 검증용 래스터 렌더링이 18회에서 2회가 된다. 저장 시 재열기 검증은 유지한다.
- 메인 페이지 렌더링과 편집이 진행되는 동안 썸네일 요청을 중단하고 기존 썸네일은 유지한다. 썸네일과 투명 이동 레이어는 사용하지 않는 텍스트 추출/글꼴 검사를 생략한다.

생성한 9페이지 공유 콘텐츠 PDF에서 이동 트랜잭션은 약 135ms였다. 8개의 비대상 페이지 이미지와 원본 바이트 보존을 별도로 검사했다. 이는 해당 합성 파일의 백엔드 측정이며 실제 사용자 파일이나 WebView 전체 응답시간을 의미하지 않는다. 사용자 PDF 자체는 제공되지 않아 직접 재현하지 못했다.

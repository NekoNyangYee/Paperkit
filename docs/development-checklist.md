# Paperkit — MVP 개발 체크리스트

체크 표시는 현재 구현 및 아래의 자동 검증 범위에 한정합니다. 모든 PDF를 편집할 수 있다는 의미는 아닙니다.

## 현재 기본 기능

- [x] pnpm/Cargo 모노레포, Tauri 2 + React, 독립적인 pdf-core.
- [x] 파일 선택/드롭, 기본 검증, 파일 정보와 확인용 썸네일.
- [x] PDFium 로딩, 페이지 렌더링/이동/확대.
- [x] 접을 수 있는 전체 페이지 사이드바와 가상 스크롤.
- [x] 오류 처리, 요청 순서 관리, 원본 읽기 전용 로딩.

## 1. 텍스트 객체 추출

- [x] 페이지의 직접 텍스트 객체에서 문자열, 사각 좌표, 폰트, 크기, RGBA 색상, 변환 행렬 추출.
- [x] 파일 ID + 문서 revision + 페이지 번호 + 객체 ID로 수정 대상 식별. 네이티브 핸들은 worker 내부에만 유지.
- [x] 객체별 편집 제한 사유 표시. 폼 내부 텍스트는 미지원 안내.
- [x] 텍스트 없는 페이지, 암호 요구, 추출/수정 권한 제한 처리.
- [x] 영문 분리 객체, 한글 임베디드 폰트, 회전/CropBox, 권한/암호 표본의 실제 DLL 테스트.
- [ ] 실제 제작 도구별 서브셋 폰트 표본 확대 검증.

## 2. 좌표 변환과 선택

- [x] PDFium의 동일한 렌더 설정으로 PDF 좌표를 이미지 좌표로 변환. CropBox/회전/렌더 크기 반영.
- [x] SVG 선택 영역, hover/키보드 강조, 한 객체 클릭 선택.
- [x] 빈 영역/Escape로 선택 취소. 적용 전 입력이 있으면 버리기 확인.
- [x] 기본 읽기 전용 안내와 ‘편집 사용’ 버튼. 편집 전 객체 클릭/수정 단축키 차단.
- [x] 본문 위치의 contenteditable 편집 레이어와 블록 테두리. 제한 사유/적용·취소는 툴바에 표시.
- [x] 본문 입력의 Ctrl+Enter 적용, IME 조합 중 단축키 무시.
- [x] 문장/문단 편집 선행 조사: [제품 비교와 문장 복원 기준](text-editing-benchmark.md).
- [x] 수평 글자/어절 객체의 문장·문단 후보 복원과 일괄 수정. 다중 객체 수정은 글자 수·공백 위치 유지 조건.
- [x] 페이지/배율 변경 시 기존 선택 초기화, 사이드바 접기 시 선택 유지.
- [x] 회전/CropBox 페이지의 400/800/1600px 렌더 글자 픽셀이 선택 좌표 안에 있는지 실제 DLL 검증.
- [ ] 실제 WebView2의 여러 Windows 화면 배율에서 클릭 위치 수동 검증.

선택 테두리는 UI 표시이며, PDF 내용에 덧붙여 저장하지 않습니다.

## 3. 실제 텍스트 객체 수정

- [x] 기존 단일 객체의 set_text, 입력/적용/취소, 페이지 콘텐츠 재생성.
- [x] 별도 문서 후보를 수정하고 직렬화 후 재열기. 실패 시 활성 문서는 유지.
- [x] 문자열/폰트/크기/색상/행렬 보존 검증. 수정 외 객체 속성 및 영역 밖/다른 페이지 픽셀 변화 거절.
- [x] 기존 경계보다 커지는 수정 거절. 자동 재배치나 폰트 대체 없음.
- [x] 성공 시 revision 증가, 이전 ID 조합 거절, 본문/썸네일 캐시 갱신.
- [x] 기본 비임베디드 Helvetica/Courier/Times 계열의 ASCII 영문·숫자·기호 편집.
- [x] 빈 입력, 제어문자, 미지원 임베디드/서브셋 폰트, 특수 텍스트 렌더링은 명확히 거절.
- [x] 동봉한 전체 폰트와 동일한 바이트가 임베딩된 객체의 한글 수정. 해시와 글리프 존재 여부 검증.
- [ ] 임의의 한글·임베디드·서브셋 폰트 수정. 현재는 지원 객체에서 동봉 폰트로 명시적으로 교체해야 함.

안전하게 거절하는 처리를 구현했으며, 제한된 폰트의 편집까지 완료된 것은 아닙니다.

## 4. 안전한 새 PDF 저장과 재검증

- [x] 변경 상태, 새 PDF 저장 대화상자, Ctrl+S.
- [x] 모든 기존 출력 경로 거절. 원본과 하드링크/심볼릭 링크도 덮어쓰지 않음.
- [x] 출력 폴더에 create_new 임시 파일 작성 및 sync_all.
- [x] 임시 파일의 실제 바이트, 재열기, 페이지 수, 전체 페이지 텍스트와 렌더 픽셀 검증.
- [x] 같은 볼륨의 hard_link로 기존 파일을 덮어쓰지 않고 최종 경로 확정. 임시 파일 정리.
- [x] 실패/대화상자 취소 시 변경 상태 유지. 저장 성공 시 저장 기준점 갱신.
- [x] 실제 파일 저장/재열기, 원본 및 원본 하드링크 덮어쓰기 거절 테스트.
- [ ] 기존 출력에 대한 명시적 덮어쓰기 기능은 미지원. 현재는 항상 새 이름을 요구.
- [ ] NTFS 외 파일시스템/네트워크 경로 검증. 하드링크가 지원되지 않으면 안전하게 실패.

## 5. Undo/Redo와 편집 UX

- [x] Rust 바이트 스냅샷 이력, Undo/Redo, 새 수정 시 redo 제거.
- [x] 이력 이동 후 revision·변경 상태·본문·썸네일 동기화.
- [x] Ctrl+Z, Ctrl+Y/Ctrl+Shift+Z. 입력창에서는 기본 텍스트 입력 Undo 유지.
- [x] 문서 닫기와 앱 종료 시 미저장 변경 확인. 처리 중 종료/중복 작업 차단.
- [x] 수정 실패 시 입력 보존, 지원하지 않는 객체 설명, 저장 실패/취소 처리.
- [x] 편집용 스냅샷은 32 MiB 이하, undo 최대 20개/128 MiB로 제한.
- [ ] 큰 문서의 저장/전체 페이지 검증 취소와 진행률 표시.

## 6. 검증과 배포

- [x] 프론트엔드 타입 검사와 프로덕션 빌드.
- [x] Rust 워크스페이스 일반 테스트 23개 (복원 표본 9개와 줄 재배치 표본 포함).
- [x] UI 자동 테스트: 기본 파일 입력, 렌더/탐색, 선택/수정, 실패 시 입력 보존, 저장 취소/실패, 종료 확인.
- [x] UI 테스트 총 39개: 기존 기능과 블록 입력·클릭 커서·IME 조합 중 확정 차단·저장 전 적용·실패 시 입력 보존 포함.
- [x] 실제 DLL 통합 테스트: 추출→좌표→수정→Undo/Redo→저장→재열기 및 오류/권한/암호/원본 보호.
- [x] Windows NSIS 설치 파일 빌드 및 PDFium DLL/라이선스 포함 확인. 설치 스크립트의 경로와 번들 DLL SHA256 대조.
- [ ] 개발 도구가 없는 별도 Windows PC에서 설치→열기→편집→저장 검증.
- [ ] 실제 Windows 대화상자/탐색기 드롭/고배율 화면 전체 수동 검증.
- [ ] 긴 문서의 응답성과 메모리 측정, 다양한 제작 도구의 PDF 표본 확대.

실행: `pnpm test:web`, `cargo test --workspace`, `pnpm test:pdfium`, `pnpm test:fonts`, `pnpm test:layout`, `pnpm build:web`.
일반 Rust 테스트에서는 DLL 테스트가 ignored이므로 전용 명령을 별도로 실행합니다.
한글 테스트는 Windows의 맑은 고딕을 임시 PDF에 임베딩하며 폰트 파일을 저장소/배포물에 넣지 않습니다.
암호·권한 표본은 직접 생성한 테스트 PDF이며 `crates/pdf-core/tests/fixtures/generate.py`로 재생성할 수 있습니다.

OCR, 문단/복잡한 레이아웃 재배치, 클라우드 동기화는 MVP 범위에서 제외합니다.

## 다음 개발 회차 — 문서 편집기 UX (2026-10-09 요청)

아래는 새 요청의 구현 체크리스트다. 계획 등록이며 아직 구현 완료를 의미하지 않는다.
새 요청으로 문장/문단 내부 편집까지 범위를 확장한다. 문서 전체와 다음 페이지로 흐르는 자동 재배치는 별도로 남긴다.

### 1. 하단 페이지 탐색

- [x] 헤더의 이전/다음 페이지와 페이지 번호를 문서 뷰어 하단 중앙으로 이동.
- [x] 문서 스크롤과 독립된 하단 바에 배치하고 마지막 페이지 내용을 가리지 않게 공간 확보.
- [x] 현재 페이지를 숫자 입력으로 표시: `이전 [현재 페이지] / 전체 페이지 다음`.
- [x] Enter로 이동, Escape로 입력 복원. 빈 값/문자/범위 초과는 안내하고 이동하지 않음.
- [x] 본문·입력 번호·왼쪽 썸네일 선택/위치를 동기화. 미적용 입력이 있으면 기존 확인 절차 유지.

검증: UI 테스트 30개와 TypeScript/프론트엔드 빌드 통과. 페이지 이동/썸네일 동기화,
잘못된 번호, Escape 복원, 미적용 편집의 이동 취소/승인 회귀 테스트 포함. 실제 Windows UI 수동 검증은 별도다.

### 2. 폰트 기반 준비 및 에디터 툴바

- [x] TTF 원본 커밋과 SHA256 고정, 라이선스/한글 글리프/실제 PDF 임베딩 검증.
- [x] 제공: Pretendard Regular, Noto Sans KR Thin, Noto Serif KR ExtraLight, 나눔고딕 Regular, 나눔명조 Regular.
- [x] 폰트와 라이선스를 리소스에 동봉하여 실행 중 오프라인 사용. 개발 준비 명령은 `pnpm setup:fonts`.
- [x] 에디터 툴바에 폰트 드롭다운 배치: 실행 취소 · 다시 실행 · [글꼴 ▾] … 새 PDF로 저장.
- [x] 선택한 단일 객체의 원본 폰트 이름 표시.
- [x] 여러 폰트가 섞인 문장/문단 선택의 ‘혼합’ 표시. 글꼴 교체는 현재 객체 선택 모드에서 제공.
- [x] 읽기 전용에서는 편집 툴바 숨김, 선택 없음/처리 중/미적용 입력에서는 비활성화. 자동 폰트 대체 없음.
- [x] 실제 PDF 객체의 폰트 교체와 재렌더링, Undo/Redo, 누락 글리프 오류. 재생성 후 객체 ID와 선택 영역 동기화.
- [x] 5종 각각 한글/영문 임베딩·텍스트 수정·저장 후 재열기와 렌더 픽셀 동일성 검증.
- [ ] 저장 후 폰트가 설치되지 않은 환경에서도 동일한 글자/배치가 보이는지 검증.

Noto 두 파일은 가변 TTF이며 현재 PDFium에서 적용되는 기본 굵기(Thin/ExtraLight)를 목록에 명시한다.
굵기 선택과 화면 입력 레이어의 정확한 폰트 일치는 후속 단계다.
글꼴 교체는 회전/기울임/클리핑/투명도 없는 지원 객체에 한정하며 원래 크기·색상·행렬을 유지한다.
새 글리프의 왼쪽 여백/높이 차이만 제한적으로 허용하고, 오른쪽 경계 확장이나 다른 텍스트와 새로 겹치는 변경은 거절한다.
폰트 전체 임베딩으로 파일 크기가 증가하며 기존 32 MiB 편집 스냅샷 제한을 유지한다.
일반 DLL 회귀 테스트 1개와 5종을 순회하는 폰트 통합 테스트 1개를 별도로 실행해 통과했다.
UI 32개, Rust 일반 테스트 13개, 프론트엔드 빌드와 Rust 포맷 검사를 통과했다.
Windows MSI/NSIS 빌드를 수행하고 NSIS 설치 스크립트에서 폰트 5개와 각 라이선스 포함을 확인했다.

후보 출처: [Pretendard](https://github.com/orioncactus/pretendard/blob/main/LICENSE),
[Noto 라이선스/사용 안내](https://notofonts.github.io/noto-docs/website/use/),
[네이버 글꼴](https://hangeul.naver.com/font).
사용량 순위를 측정한 목록이 아닌 한글 문서용 추천 목록이다. 다운로드 원본과 해시는 `scripts/fonts-manifest.json`에 기록한다.

### 3. 문장·문단 복원

- [x] PDF 문자 배치 경계·기준선·간격으로 객체→줄→문단 후보→문장을 구성. 화면 배율과 독립된 PDF 좌표 사용.
- [x] 원본 객체 ID·문자 범위와 객체별 폰트/크기/색상 매핑 유지. 오프셋은 Unicode scalar 단위.
- [x] 영문 글자별 객체와 한글 어절별 객체의 같은 문장 복원 표본 테스트.
- [x] 여러 줄 문장, 한 줄의 여러 문장, 약어/소수/URL, 혼합 서식, 두 단/표 선의 휴리스틱 표본 검증.
- [x] 같은 행의 분리된 열·셀은 독립 편집 대상으로 처리. 실제 겹침은 불확실 표시하고 경계선과 큰 간격에서 병합 중단.
- [x] 여러 객체 수정은 한 트랜잭션/한 Undo로 처리. 최종 문자열·run 매핑 재검증, 실패 전체 취소, 오래된 revision 거절.
- [x] 툴바 ‘블록 선택 / 문장 선택 / 객체 선택’. 4단계부터 기본은 문단의 외곽을 하나로 잡는 블록 선택.
- [ ] 실제 제작 도구별 다단·복잡한 표·들여쓰기·언어별 문장부호 표본 확대와 정량 정확도 측정.

현재 복원은 수평 본문을 대상으로 하는 보수적인 좌표 휴리스틱이다. PDF 논리 구조 태그, 회전/세로쓰기,
합자/불명확한 문자 매핑은 자동 복원하지 않는다. 표 선은 경로 객체의 경계를 기준으로 보수적으로 처리한다.
문장과 혼합 서식 문단의 다중 객체 수정은 **글자 수와 공백 위치를 유지**하며 원래 글자 배치 폭 안에서 허용한다.
서로 다른 객체의 폰트/색상/행렬은 유지하고, 인접 객체와 새로 겹치거나 범위를 넘으면 전체를 거절한다.
원본 객체 전체에 해당하는 단일 그룹은 기존 가변 길이 수정 경로를 사용한다. 같은 서식의 블록은 아래 4단계의 줄 재배치를 제공한다.
페이지당 객체 2,048개 또는 문자 12,000개 초과 시 복원을 생략하고 안내한다. 그룹 편집은 최대 128개 run이다.
썸네일에는 복원 계산을 하지 않는다. 다중 객체 적용 시 객체별 검증 비용이 있어 긴 문서 성능 개선은 남아 있다.

검증: UI 35개, Rust 일반 테스트 22개, 실제 DLL 통합 테스트 3개 통과.
문장 DLL 표본은 배율 독립성·회전 객체 제외·부분 문장 수정·중간 실패 전체 취소·한 번의 Undo·저장 재열기를 확인한다.
폰트 DLL 표본에는 Pretendard 한글 어절 3개를 문장으로 복원하고 음절 교체 후 Undo하는 검증을 추가했다.
실제 Windows 화면의 커서/선택 시각 검증과 다양한 제작 도구의 PDF 실사용 검증은 별도다.

- [x] 실패 시 입력과 현재 페이지 유지. 저장 전 확정 실패 시 저장 대화상자를 열지 않음. 성공 후 새 revision/객체 ID 사용.
- [x] 동일 서식의 완전한 블록에서 길이 변경·자동 줄바꿈·명시적 줄바꿈·전체 삭제 지원. 기존 블록 폭과 줄 수 안에서 처리.
- [x] 혼합 서식·부분 객체·불확실한 블록은 기존 범위 수정 또는 읽기 전용으로 제한. 주변 텍스트 침범과 영역 밖 픽셀 변화 거절.
- [x] 원본 객체를 제거하고 새 줄의 실제 PDF 텍스트 객체로 재구성. PDF에 흰 사각형/주석을 덧씌우지 않으며 한 번의 Undo로 복구.

실제 DLL 검증: 영문 글자별 객체를 짧은 블록으로 교체·초과 거절·전체 삭제·Undo/Redo·저장 재열기,
Pretendard 한글 두 줄 블록의 명시적 줄바꿈 후 저장·재열기, 긴 문장의 자동 줄바꿈과 문자 보존도 확인했다.
변경 밖 객체 속성과 다른 페이지/영역의 픽셀을 비교한다. UI 39개, Rust 일반 23개, 실제 DLL 통합 3개와 Windows MSI/NSIS 빌드를 통과했다.
자동 테스트는 OS의 실제 IME 입력기와 화면 배율 시각 검증을 대체하지 않는다.
혼합 서식 블록의 자유로운 재배치는 남아 있다. 크기·색·변환이 같은 완전한 문단은 블록 전체 글꼴 변경을 지원한다.

# 텍스트 반영 실패 조사

여러 문서에서 나타나는 `VerificationFailed`는 하나의 원인을 뜻하지 않는다.

- 수정한 글자의 변환 행렬을 완전 일치로 비교해 PDF 재저장 시 `0.75 → 0.74999994` 같은 부동소수점 오차를 거부했다. 배율·회전 성분의 비교에 0.00001 미만 허용 오차를 적용했다. 문자·폰트·색상과 주변 픽셀 검증은 유지한다.
- 로컬 Invoice PDF에서는 별도로, PDFium의 페이지 재구성 후 수정하지 않은 글자 객체가 누락되는 현상을 확인했다. 이 경우는 아직 지원 제한이며 검증을 우회하지 않는다. `UnchangedTextModified`로 구분해 원본의 다른 글자를 보존하지 못한 이유를 안내한다.
- 원본 서브셋 폰트에 입력 문자가 없는 `MissingGlyph`, 원본 폰트를 사용할 수 없는 `FontUnavailable`도 별도 원인이다. 검증 오차 수정으로 이 제한까지 해결되는 것은 아니다.

`probe_edits` 예제는 지정한 로컬 PDF의 편집 가능한 첫 8개 블록에 문자열을 추가해 메모리에서 확인한다. 원본은 저장하거나 덮어쓰지 않는다. 네이티브 FlowBlock 경로를 확인하는 도구이며 프론트의 글꼴 선택 동작 전체를 대체하지 않는다.

축소 배율을 가진 텍스트의 수정·저장·재열기·실행 취소와 원본 보존을 회귀 테스트에 추가했다.

# PDF 회귀 검사 범위 — 2026-10-10

현재 프로젝트 폴더의 PDF를 검색했다. 일반 문서 PDF는 없고 다음 두 원본만 존재했다.
따라서 사용자 인보이스나 모든 제작 도구의 PDF가 검증되었다고 해석하면 안 된다.

| 기존 PDF                                        | 검사 내용                                  |
| ----------------------------------------------- | ------------------------------------------ |
| `crates/pdf-core/tests/fixtures/password.pdf`   | 암호 없이 열기 거절, PasswordRequired      |
| `crates/pdf-core/tests/fixtures/restricted.pdf` | 텍스트 추출 권한 제한 표시, 내용 수정 차단 |

`corpus_smoke`는 임시 디렉터리에 다음 표본을 생성하고 원본 바이트를 보존하며 검증한다.

| 추가 생성 표본               | 블록 | 검사 내용                                                      |
| ---------------------------- | ---- | -------------------------------------------------------------- |
| 단일 열 5줄 문단             | 1    | 묶기, 내용 수정, 이동, 범위 초과 거절, Undo, 저장·재열기       |
| 인보이스형 3열 × 4줄         | 3    | 객체가 행별로 섞여 있어도 각 열 복원, 모든 블록 수정·이동·저장 |
| 세로 경계선이 있는 3열 표    | 3    | 셀 사이 병합 방지, 각 셀의 수정·이동·저장                      |
| 90도 회전 페이지             | 1    | PDF 좌표와 회전된 화면 좌표 구분, 이동·수정·저장               |
| 크기·색상이 다른 제목과 본문 | 1    | 큰 블록 복원, 서식 보존, 긴 내용 확장·저장 재열기              |

후속 검증에는 기존 줄 수를 초과하는 긴 내용, 너비 150pt의 재배치, 배경만 렌더링한 뒤 활성 문서가 변하지 않았는지 확인하는 검사를 추가했다.
맑은 고딕 내장 원본에서는 실제 글꼴 데이터 추출과 같은 글꼴을 유지하는 한글 장문 편집·저장·재열기를 확인했다.

기존 네이티브 테스트도 함께 실행한다.

- `fonts_smoke`: 제공 글꼴 5종, 한글 어절·여러 줄 문단, 맑은 고딕 원본의 폰트 유지 이동과 기본 Pretendard 자동 편집, 명시적 글꼴 변경, Undo/Redo, 저장 재열기.
- `layout_smoke`: 영문 글자별 객체, 문장 부분 수정, 원자적 실패 취소, 블록 재배치·삭제, 저장과 오래된 ID 거절.
- `pdfium_smoke`: 로딩·페이지 이동·캐시·문서 해제·암호·권한·CropBox·회전·오류 처리.
- UI: 클릭 선택/더블 클릭 편집, 원본 미지원 글꼴의 기본 글꼴 편집, 드래그의 PDF 좌표 변환, IME 중 적용 차단, 초안 보존, 저장 흐름.

실행: `pnpm test:rust`, `pnpm test:web`, `pnpm test:corpus`, `pnpm test:fonts`, `pnpm test:layout`, `pnpm test:pdfium`.
가변 블록 후속 자동 검사 결과: UI/좌표/원본 글꼴 46개, Rust 일반 29개, 실제 PDFium 통합 4개 통과. TypeScript와 Rust 포맷 검사, Windows MSI/NSIS 설치 파일 빌드 통과.
실제 OS IME·포인터 조작·다양한 제작 도구의 임의 PDF에 대한 수동 시각 검증은 별도로 남아 있다.

## 이동 후 화면 유지 및 브라우저 선택 방지 (2026-10-10)

- 같은 페이지 재렌더링 시 기존 페이지 DOM을 제거하지 않고 새 이미지 디코딩 후 교체한다. 이동 미리보기도 교체까지 유지한다. 다른 페이지로 이동할 때에는 이전 페이지를 숨긴다.
- 썸네일 사이드바는 문서 수정마다 재마운트하지 않는다. revision으로 캐시를 갱신하면서 기존 이미지와 스크롤 위치를 보존한다.
- 편집 화면에는 select-none, 실제 contenteditable에는 select-text를 적용했다. PDF 및 썸네일 이미지의 기본 드래그를 차단했다.
- 검증: UI 59개 및 TypeScript/Vite 빌드 통과. 지연된 이동 후 렌더링에서 기존 DOM/이동 레이어/스크롤 유지, 교체 후 레이어 제거, 썸네일 갱신 중 기존 이미지 유지 검사를 포함한다.
- 실제 WebView에서 더블클릭/텍스트 드래그의 시각적 동작은 수동 검증하지 않았다. 기존 번들 크기 및 PURE 주석 경고는 유지된다.

## 원본 글꼴 보존 우선 (2026-10-10)

- 화면의 자동 Pretendard 전환과 문단 저장 시 자동 대체를 제거했다. 원본을 사용할 수 없는 객체는 그대로 선택하고 안내하며, 사용자가 드롭다운으로 글꼴을 선택한 경우에만 대체한다.
- PDF 내장 글꼴의 Unicode cmap/필요 문자/임베딩 허용 여부를 우선 확인한다. 사용할 수 없으면 Windows Fonts 및 사용자 Microsoft/Windows/Fonts에서 같은 전체 이름 또는 PostScript 이름의 글꼴을 찾는다. PDF 서브셋 접두사만 제거하며 Regular/Bold를 서로 대체하지 않는다.
- 설치 글꼴의 TrueType 윤곽선 TTF 및 TTC face를 지원한다. TTC는 테이블 오프셋과 체크섬을 재생성해 단일 sfnt로 추출하고, 화면 FontFace와 PDFium에 전달한다. CFF 전용 설치 글꼴과 임의 외부 경로/글꼴 파일 선택 UI는 이번 범위에 포함하지 않는다. 설치 목록은 프로세스 단위로 유지하므로 새 글꼴 설치 후 앱 재시작이 필요하다.
- 입력 글자가 내장 글꼴에 없으면 동일 설치 글꼴로 재시도한다. 동일 글꼴도 없으면 입력/원본을 보존하고 오류를 표시한다. 글자별 이종 글꼴 혼합 대체는 자동 수행하지 않는다. PDF 기본 Helvetica/Courier/Times의 브라우저 표시는 기존 표준 글꼴 대응을 유지하므로 완전한 픽셀 일치를 보장하지 않는다.
- 설치된 맑은 고딕 Bold와 굴림을 사용하는 PDF의 편집/새 파일 저장/재열기/원본 바이트 보존을 확인했다. 없는 글꼴의 문단 편집은 FontUnavailable로 실패하며 revision과 페이지 이미지가 유지된다. TTC 체크섬, 한글 글리프 및 굵기 구분도 검증했다.
- UI 60개, Rust 일반 34개 통과. TypeScript/Vite 빌드 통과(기존 경고 유지). 네이티브 테스트의 묶음 실행에서는 PDFium 초기화/종료 충돌이 발생했다. test:fonts/test:corpus 명령은 각 테스트를 별도 프로세스로 실행하도록 변경했다.
- 최종 네이티브 검증: PDFium 통합 7개는 각각 별도 프로세스에서 모두 통과했고, 설치 TTC 추출 검사 1개도 통과했다. 사용자 원본 PDF 및 실제 WebView의 글꼴 외관은 별도로 확인하지 못했다.

## 기본 제공 글꼴 확장 (2026-10-10)

- 기본 제공은 5개에서 27개 파일(11개 계열)로 확대했다. 전체 목록과 라이선스 출처는 `font-catalog.md`에 정리했다. TTF 97,354,860 bytes와 글꼴별 라이선스를 리소스에 포함하며 고정 커밋/해시로 재설치한다.
- 글꼴 메뉴를 기본 제공/이 PC의 글꼴로 구분했다. Windows 및 Office/한컴 글꼴은 설치된 항목을 연결하며 리소스에 복제하지 않는다. 설치 글꼴 선택은 installed: 식별자로 처리하고 클라이언트에서 파일 경로를 전달하지 않는다.
- 원본과 이름이 같은 기본 제공 파일도 원본 글꼴 재사용 탐색에 포함했다. 제공 글꼴 목록의 PostScript 이름으로 스타일을 식별한다.
- UI 61개, Rust 일반 34개 및 TypeScript/Vite 빌드 통과. 27개 제공 글꼴별 실제 PDFium 교체/없는 문자 거부/Undo/Redo/저장/재열기 검증 통과. 한글 글꼴은 한글 수정, Carlito/Caladea는 영문 검사를 적용했다. 설치 글꼴 및 번들 동일-face 검색 검사도 통과했다.
- 발견한 제한: 나눔명조 ExtraBold는 공백 손실로 제외했다. 비내장 Pretendard-Bold 두 객체 중 하나만 임베디드 글꼴로 교체하는 혼합 표본에서는 저장 재검증이 실패했다. 검증을 완화하지 않았으며 이 경우 저장은 거부된다. 번들 동일-face 성공 표본은 비내장 단일 객체로 별도 확인했다. 모든 제작 도구/혼합 글꼴 PDF의 편집·저장을 보장하지 않는다.

# 원본 글꼴 유지 편집

- 편집 진입과 새 문자 검증에서 유사 글꼴 자동 선택을 하지 않는다.
- PDF 내장 글꼴을 우선 검증하고, 사용할 수 없으면 동일한 전체 이름 또는 PostScript 이름의 글꼴을 찾는다.
- `원본 글꼴 불러오기`로 TTF/TTC를 선택할 수 있다. PDF의 6자리 서브셋 접두사는 이름 비교에서 제외하며, 굵기와 스타일 접미사는 유지한다.
- 등록한 글꼴 데이터는 앱 프로세스 메모리에만 보관한다. Windows 설치나 원본 글꼴 파일 수정은 하지 않는다. 앱을 종료하면 다시 불러와야 한다.
- 읽기는 32 MB, 등록 총량은 128 MB로 제한한다. 불일치·지원하지 않는 형식·임베딩 제한이 있으면 등록하지 않는다.
- 새 글자가 없으면 문서 변경을 중단하고 입력을 유지한다. 입력 중 동일 글꼴을 불러온 뒤 다시 적용할 수 있다.
- 글꼴 드롭다운을 통한 사용자의 명시적인 글꼴 변경은 유지한다.

## 지원 범위

이름 일치는 동일 버전의 폰트 파일까지 증명하지 않는다. 가능하면 문서 제작에 사용한 파일을 선택해야 한다. 임의로 이름을 바꿔 다른 글꼴을 원본으로 등록하지 않는다.

현재 불러오기는 TrueType 윤곽선과 사용 가능한 Unicode cmap이 있는 TTF/TTC를 지원한다. 내장 글꼴에 Unicode cmap이 없으면 Type0 / Identity-H / CIDFontType2의 ToUnicode 및 명시적인 CIDToGIDMap으로 복원한다. 내장 FontFile2 바이트가 정확히 일치하는 글꼴만 처리하고, 충돌하는 매핑과 한 글리프에 여러 문자가 연결된 경우는 추측하지 않는다. Unicode 비문자(예: U+FFFF)는 매핑에서 제외한다. 글자 윤곽선·폭·힌팅은 그대로 두고 cmap과 체크섬을 재구성한다. PDF 서브셋에 OS/2, name, post가 빠져 있으면 브라우저용 메타데이터를 보완한다. 기존 OS/2의 명시적인 제한은 덮어쓰지 않는다. 이 복원 글꼴은 OS에 설치하지 않는다.

CFF/Type 1 및 다른 사용자 정의 인코딩의 복원은 아직 지원하지 않는다. 서브셋에 없는 글자 모양을 생성하거나 원본과 다른 글꼴로 숨겨서 대체하지 않는다. PDF 기본 14 글꼴은 기존 표준 글꼴 경로를 유지한다. 모든 PDF의 임의의 새 문자를 원본 글꼴로 편집할 수 있다는 보장은 하지 않는다.

## 검증

- 프론트 회귀: 원본 글꼴 누락 시 자동 대체 요청 없음, 새 문자 검증 실패 시 입력 보존, 원본 파일 가져오기 후 동일 입력 재적용.
- PDFium 통합: 다른 굵기 등록 거부, 서브셋 이름 매칭, 앱 세션 글꼴 로딩, 한글 입력 및 저장 후 재열기, 원본 바이트 보존.
- STK 실제 문서: HCRBatang 원본 서브셋의 glyf/hmtx/loca 일치, `전시 종료 후 당일 철거`에 `dd` 추가, 저장 후 렌더링 일치, 원본 바이트 보존. `PAPERKIT_TEST_PDF`를 지정하고 `cargo test -p pdf-core stk_original_subset_edits_and_roundtrips -- --ignored --nocapture`로 실행한다. 사용자 PDF는 저장소에 포함하지 않는다.
- 복원한 STK 본문 글꼴을 Edge Chromium의 실제 FontFace로 로딩하여 성공을 확인했다. Tauri 앱 전체의 마우스 입력 검증과는 별개다.

## 편집 성능

- 변경 결과 검증은 텍스트·글꼴 이름·크기·색상·좌표·페이지 픽셀 비교를 유지하면서, 편집 세션용 글꼴 복원을 다시 수행하지 않는다.
- 복원 결과는 PDF 전체 내용과 내장 글꼴 바이트를 함께 해시한 키로 재사용한다. 서로 다른 문서의 문자 매핑이 섞이지 않으며, 작업 스레드별 최대 32개/16 MB로 제한한다.
- 2026-10-11 동일 STK 문서에 `dd`를 추가한 개발 빌드 단일 측정: 수정 반영 4,728 → 2,191 ms, 이후 화면 렌더링 937 → 791 ms, 저장 112 → 109 ms. 실행 환경과 문서에 따라 달라지며 앱 전체 입력 지연을 뜻하지 않는다. 저장 시 디스크 기록·재열기·전체 페이지 검사는 유지했다.
